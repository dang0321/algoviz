# algoviz

### ▶ 바로 쓰기 — https://dang0321.github.io/algoviz/

설치도 로그인도 필요 없다. 브라우저만 있으면 어디서든 열린다.
(첫 로딩에 파이썬 약 10MB 를 받아서 10~30초 걸린다. 그다음부터는 빠르다.)


파이썬 코드를 넣으면 **한 줄씩 실행되는 모습을 그림으로 재생**해준다.
알고리즘 문제 풀 때 print 를 박아가며 확인하던 걸, 모든 시점을 미리 다 찍어두고
슬라이더로 훑어보는 방식으로 바꾼 것.

## 왜 만드나

- **Python Tutor**: 내 코드는 되는데 정지 화면 + 힙으로 뻗는 화살표. 안 움직인다.
- **알고리즘 시각화 사이트**: 막대가 예쁘게 움직이는데 미리 만들어둔 알고리즘만 된다.

이 둘의 교집합 — **내가 짠 코드가 움직이는 그림이 되는 것** — 이 비어 있다.

## 실행

```
python serve.py
```

브라우저에서 http://localhost:8765

`file://` 로 열면 안 된다. Pyodide 가 wasm 을 fetch 해야 해서 http 가 필요하다.
Claude Code 에서는 `.claude/launch.json` 의 `algoviz` 설정으로 바로 뜬다.

**`python -m http.server` 를 쓰면 안 된다.** Cache-Control 헤더를 안 보내서
브라우저가 알아서 캐시해버리고, 코드를 고쳐도 새로고침해도 옛 파일이 계속 돈다.
`serve.py` 는 매 응답에 `no-store` 를 붙인다. 이 도구는 고치고 바로 눈으로
확인하는 게 전부라 그 버그 하나로 작업이 통째로 막힌다. (두 번 당했다)

이미 캐시된 게 남아 있으면 한 번은 강제 새로고침(Ctrl+Shift+R)이 필요하다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `tracer.py` | `sys.settrace` 로 한 줄마다 변수를 통째로 스냅샷 → JSON 타임라인 |
| `app.js` | Pyodide 로딩, 실행, 재생 루프, 에디터/플레이어 조작 |
| **`viz-util.js`** | 이 값이 무엇처럼 생겼는가 (공용 판별기·포맷터) |
| **`viz-layout.js`** | DOM/SVG 만들기, 트리·원형 좌표 계산 |
| **`viz-explain.js`** | 그림 옆에 붙는 **말** (주석·단계·역할·구간) |
| **`viz-detect.js`** | 타임라인 보고 **뭘 그릴지 정한다** ← 유형 추가는 여기 |
| **`viz-render.js`** | 화면에 만들고 프레임마다 갱신한다 |
| `viz.js` | 위 셋을 묶는 겉면 (`analyze` / `mount` / `update`) |
| `samples.js` | 예제 코드. 여기 추가하면 드롭다운에 뜬다 (index.html 의 option 도 같이) |
| `serve.py` | 개발용 정적 서버. 매 응답에 no-store 를 붙여 캐시를 막는다 |

`index.html` 에서 **util → layout → explain → detect → render → viz** 순서로 읽어야 한다.
번들러가 없어서 각 파일이 IIFE 로 전역 하나(`VizUtil` 등)를 만들고, 다음 파일이
맨 위에서 구조 분해로 가져다 쓴다. 새 파일을 만들면 script 태그 순서를 맞출 것.

### 새 알고리즘 유형을 추가하려면

1. `viz-detect.js` 에 `findXxx(timeline, seen)` 를 만든다 — **이름이 아니라 쓰이는
   방식으로** 판정한다 (아래 판정 규칙 참고)
2. `analyze()` 에서 불러 `blocks` 에 넣고, 겹치는 다른 블록에서 그 변수를 뺀다
3. `viz-render.js` 의 `titleOf` / `mountBody` 에 분기를 더하고 `update()` 에 갱신 코드를 쓴다
4. `samples.js` + `index.html` 에 예제를 넣는다

서버가 필요 없다. 파이썬이 브라우저 안(WASM)에서 도니까 정적 호스팅이면 배포 끝이고,
남의 코드를 내 서버에서 실행하는 보안 문제도 없다. 무한루프를 짜도 그 사람 탭만 멈춘다.

## 입력 (stdin)

에디터 아래 **입력** 칸에 넣은 내용을 `input()` 이 한 줄씩 읽는다.
백준/프로그래머스 코드를 그대로 붙여넣을 수 있다.

브라우저에는 진짜 stdin 이 없어서 두 군데를 갈아끼운다 (`tracer.py` 의 `run()`):
- `input` 을 실행 전역(`g`)에 넣는다 → 빌트인보다 먼저 잡힌다
- `sys.stdin` 을 `StringIO` 로 바꾼다 → `sys.stdin.readline` / `.read()` 도 된다

입력이 모자라면 `EOFError` 로 몇 번째 줄인지 알려주고, **거기까지의 실행은 그대로 재생된다.**

## 작성 중인 코드는 남는다

새로고침해도 코드·입력·정지줄이 그대로 복원된다 (`localStorage`).
Pyodide 로딩 때문에 새로고침이 잦은데 매번 코드가 날아가면 매일 쓰는 도구가 못 된다.
사생활 보호 모드처럼 저장이 막히는 환경에서는 조용히 넘어간다.

## 오류가 나면 그 줄로 데려간다

에러가 있으면 자동 재생 대신 **터진 줄이 실행된 마지막 시점**으로 바로 이동한다.
처음부터 재생시키면 원인을 보러 되돌아와야 한다.

## 출력

`print` 출력은 **재생 시점에 맞춰 조금씩 드러난다.** 한꺼번에 다 보여주면
"지금 어디까지 찍혔나"를 알 수 없어서, 각 프레임에 기록해둔 출력 길이만큼만 자른다.

## 설계에서 중요한 것 (건드릴 때 주의)

**1. DOM 을 매 프레임 새로 만들지 않는다.**
속성만 바꿔야 CSS 트랜지션이 살아서 막대가 "스르륵" 움직인다.
새로 만들면 그냥 뚝뚝 끊긴다. 이게 이 도구의 존재 이유라 절대 깨면 안 된다.

**1-2. 캐시를 두 군데서 막아야 한다.**
`tracer.py` 는 `fetch(..., {cache: "no-store"})` 로 가져오고, 나머지 파일은
`serve.py` 가 `no-store` 헤더를 붙여서 막는다. 두 번 다 같은 증상으로 당했다 —
고쳤는데 계속 옛 코드가 돌아서 없는 버그를 쫓았다.

**1-3. 트리 x 좌표는 반드시 DFS 순서로 매긴다.**
잎 번호를 BFS(또는 역방향 BFS) 순서로 매기면 형제 subtree 의 잎이 뒤섞여
부모끼리 **같은 자리에 겹친다.** 실제로 노드 2 와 3 이 정확히 같은 x 로 계산돼
하나가 화면에서 사라졌다. 겹침은 눈으로는 "노드가 없어졌다"로 보여서 원인을
엉뚱한 데서 찾게 된다. 회귀 확인은 노드 좌표를 뽑아 중복이 있는지 세면 된다.

**1-4. 스냅샷에 전역까지 담아야 한다.**
지역변수만 담으면 **함수 안으로 들어가는 순간 화면이 통째로 빈다.**
유니온 파인드의 `parent`, 퀵소트의 `arr` 처럼 전역 자료구조를 함수가 만지는 코드가
흔한데, 정작 그 함수 안에 있는 동안(= 대부분의 시간) 아무것도 안 보이게 된다.
`_locals_of` 가 전역을 깔고 지역으로 덮는다.
**단 호출 스택의 인자는 `_only_locals` 로 따로 뜬다** — 안 그러면
`find(parent=[...], a=1, b=2, x=1)` 처럼 남의 변수가 인자인 척한다.

**2. 막대 높이 기준은 전체 타임라인의 최대값으로 고정한다.**
프레임마다 다시 정규화하면 값이 안 변해도 막대가 출렁여서 아무것도 못 읽는다.

**3. 뭘 그릴지는 추측이다.** `viz.js` 의 `analyze()` 가 규칙으로 정한다.
- 숫자 리스트(3칸 이상, 2프레임 이상 존재) → 막대. 2칸짜리 결과 튜플을 배열로
  착각하면 화면을 통째로 차지해서 이 조건이 필요했다
- 숫자 2차원 리스트 → 표 (DP). **단 0/1 만 쓰면 숫자 표가 아니라 지도로 그린다** —
  미로의 벽, N퀸의 보드는 칸이 찼나 비었나가 전부다. 배열도 마찬가지로
  0/1 만 담으면 켜짐/꺼짐으로 그린다 (`visited = [0]*n`)
- 배열은 **400칸까지** 받는다. 40칸이 넘으면 막대를 얇게 하고 숫자 라벨을 뗀다.
  64 로 막아두면 실제 문제의 n=100 짜리 입력이 통째로 안 보인다
- **주 배열 = 가장 긴 배열.** 포인터를 여기 붙이므로 "실제 데이터"가 와야 한다.
  변화량 순으로 고르면 결과 변수가 뽑혀서 포인터가 전부 어긋난다
- **호출 스택 = 함수 호출.** `tracer.py` 가 남긴 depth 로 매 시점의 스택을 되살린다.
  call 이벤트의 지역변수가 곧 그 호출에 넘어온 인자다. 재귀가 있으면 늘 맨 위에 온다
- **문자 격자 = 글자 표 + 강조.** `[['#','.','#'], ...]` 는 숫자 격자도 문자열도 아니라
  통째로 안 보였다. 한국 코테는 격자를 숫자보다 문자로 주는 경우가 더 많다.
  **어느 글자가 벽인지는 사전순으로 정하면 안 된다** (`.` 가 `#` 보다 뒤라서 길을
  칠하고 벽을 비웠다). 적게 나오는 글자를 칠하되, 글자는 늘 보여주므로 추측이
  틀려도 읽는 데 지장이 없다
- **세그먼트 트리의 질의·갱신은 노드 강조로 보인다.** 트리를 그려도 "이 질의가
  어느 노드를 훑나"가 안 보이면 반쪽이다. 트리 번호 범위(1 ~ len-1) 안에서 움직이는
  정수를 커서로 보고 그 노드에 테두리를, 값이 방금 바뀐 노드에는 색을 준다.
  갱신이 잎에서 뿌리까지 올라가는 게 그대로 보인다
- **세그먼트 트리 = 1-기반 완전이진트리.** `tree[i] == tree[2i] (+|min|max) tree[2i+1]` 이
  **모든 내부 노드에서 정확히** 성립해야 한다. 근사치를 받아주면 0 으로 채워진
  `dist`·`parent`·`indeg` 가 죄다 "구간최소 트리"로 잡힌다 (값이 같으면 min/max 가
  저절로 성립하기 때문). 길이가 짝수이고 8 이상, 서로 다른 값이 3개 이상이어야 한다
- **비트마스크 = 2진수 병기.** 소스에서 `&`, `|`, `^`, `<<`, `>>` 옆에 붙은 이름을 찾아
  변수 패널에 `mask 13 1101` 처럼 같이 쓴다. **꺾은선으로 간 값도 마찬가지** —
  `mask` 가 시계열로 그려지면 범례에서 2진수를 놓치고 있었다
- **2차원 참/거짓 표도 격자다.** `pal[i][j] = True` 같은 표는 숫자 격자도 문자 격자도
  아니라 통째로 안 보였다. 회문 분할 DP, 도달 가능성 표가 다 이 모양이다.
  1차원 bool(체·visited)은 이미 그리고 있었는데 2차원만 빠져 있었다.
  0/1 로 바꿔서 **0/1 지도와 같은 길로 보낸다** — 그려지는 모습이 "찼나 비었나"로
  똑같으므로 그리는 코드를 따로 둘 이유가 없다
- **참/거짓 배열 = 켜진 칸.** `[True, False, ...]` 는 숫자가 아니라 막대도 안 되고
  글자도 아니라 칸도 안 됐다. 체·방문표시는 워낙 흔해서 따로 그린다
- **상수 표는 안 그린다.** 한 번도 안 변하는 딕셔너리는 세는 게 아니라 상수 표다.
  수식 계산기의 `prec = {"+": 1, "*": 2}` 가 막대그래프로 떠서 화면을 먹었다.
  세는 딕셔너리의 서명은 **값이 자란다**는 것이다 (방향 벡터를 뺀 것과 같은 이유)
- **세는 딕셔너리 = 키별 가로 막대.** `{"a": 3, "b": 2}` 를 중괄호로 찍으면
  "뭐가 제일 많나"가 안 보인다. 값이 전부 숫자인 딕셔너리가 대상
  (값이 리스트면 인접구조라 그래프로 간다)
- **메모이제이션 표 = 2차원 표.** `memo[(i, j)] = ...` 로 채우는 재귀 DP 는
  파이썬에서 제일 흔한 DP 모양인데 딕셔너리라서 화면에 아무것도 안 나왔다.
  **키가 전부 정수 두 개짜리 튜플이면 그건 사실 2차원 표다.** 표로 펴고,
  아직 계산 안 된 칸은 **비워 둔다** — 0 으로 채우면 "계산해서 0"과 구별이 안 된다.
  재귀는 깊은 곳부터 값이 정해지므로 칸이 켜지는 순서가 곧 계산 순서의 설명이 된다.
  (튜플 키가 전부 `?` 로 뭉개져서 "세는 딕셔너리"에서도 빠지고 있었다 — `dictKey`)
- **우선순위 큐 = (값, 대상) 줄.** `heapq` 에 `(거리, 노드)` 를 넣는 다익스트라·프림은
  값이 2열 리스트라 통째로 안 보였다. 핵심은 "다음에 뭐가 꺼내지나"라서 **맨 앞을
  강조해서** 줄로 세운다. 이름(`pq`, `heap`)이 아니라 성질로 가른다 —
  넣기와 빼기를 둘 다 하고, **맨 앞이 거의 항상 첫 값이 가장 작은 원소**여야 한다
- **재귀 호출 트리 = 갈라지는 점.** 호출 스택은 "지금 어디까지 파고들었나"는
  보여주지만 **전부 몇 번 불렸나**는 못 보여준다. `fib(6)` 은 25번 불리는데
  스택은 최대 6칸이라 "왜 지수 시간인가"가 그림에서 안 보였다.
  호출 하나를 점으로 놓고 부른 관계를 선으로 이으면 같은 `fib(3)` 이 여러 갈래에서
  다시 계산되는 게 눈에 보인다 — 메모이제이션과의 대비가 바로 이 그림이다.
  **안 갈라지는 재귀(팩토리얼)는 안 그린다** — 한 줄로 늘어선 트리는 호출 스택과
  똑같은 그림이라 화면만 두 배로 먹는다. 호출 160개까지
- **좌표 평면 = 산점도.** `pts = [(2,3), (12,30), ...]` 를 2열 표로 그리면 숫자만
  읽힌다. "어느 두 점이 가까운가"는 표로는 절대 안 보인다. 쌍 목록이 좌표인지
  구간인지 간선인지는 데이터로 못 가르므로 **코드를 근거로 쓴다** —
  `pts[i][0]`, `pts[i][1]` 처럼 두 성분을 따로 꺼내 쓰거나 `for x, y in pts` 로
  풀어 쓰면 그건 x 와 y 다. 둘 다 없으면 안 그린다
- **인접 행렬 = 그래프 + 표.** SWEA 는 그래프를 인접 리스트가 아니라 **n x n 행렬**로
  주는 경우가 많다. `cost[u][v]` 로 도는 다익스트라를 돌려보면 표만 뜨고 그래프가
  안 나왔다. 표로는 "누가 누구와 이어졌나"가 절대 안 보인다. **표는 그대로 두고**
  그래프를 하나 더 그린다 (`cost` 와 `cost 연결`) — 코드를 따라가려면 표도 필요하다.
  조건을 세게 잡는다: 정사각 + 대각선이 전부 0 + **한 번도 안 변함**(계산으로 채우는
  DP 표가 아니라 문제가 준 입력) + 0 인 칸이 하나는 있음.
  **미로 지도도 정사각에 대각선이 0 일 수 있다.** 미로의 행·열은 공간상의 위치고
  인접 행렬의 행·열은 노드의 정체다. 가르는 신호: 미로에는 같은 크기의 다른 격자
  (BFS 의 `dist`)가 반드시 따라오고, 인접 행렬의 짝은 1차원 배열이다
- **레코드 표 = 섞인 튜플 리스트.** `people = [(21, 0, "Junkyu"), ...]` 는 숫자 격자도
  문자열도 아니라 통째로 안 보였다. 그런데 나이순 정렬 같은 문제에서 이게 곧 데이터다.
  표로 눕히면 정렬로 줄이 어떻게 뒤바뀌는지가 그대로 보인다.
  **한 열이라도 숫자가 아닐 때만** 여기서 그린다 — 숫자만이면 이미 다른 그림
  (격자·구간·산점도)이 맡는다
- **이미 그린 자료의 조각은 안 그린다.** `for row in board:` 의 `row`,
  `for age, idx, name in people:` 의 `name` 은 원본을 보면 되는 부스러기인데
  각자 블록을 하나씩 받아 갔다. 격자를 출력하는 마지막 두 줄 때문에 막대가
  하나 더 붙는 식이었다. 소스의 `for ... in <이름>` 을 읽어서, 그 `<이름>` 이 이미
  그려졌으면 조각은 뺀다. **두 글자짜리 문자열 블록**(`a, name = input().split()` 의 `a`)도 뺀다
- **노드가 숫자가 아니어도 그래프다.** `graph = {"서울": ["대전", ...]}` 처럼 도시 이름·
  단어를 노드로 쓰는 문제가 흔한데 통째로 안 보였다. 키가 14자 이하 문자열이면 노드로
  받는다. 어느 쪽이 이웃인지는 여전히 **키 집합에 있는가**로 가리므로,
  `{"과일": ["사과", "배"]}` 같은 그냥 분류 딕셔너리는 안 걸린다.
  글자 노드에서는 커서도 글자다 — **값이 한 번도 빠짐없이 노드 이름**이어야 커서로 본다
- **격자 위에서 바라보는 방향 = 칸 안의 삼각형.** 로봇 청소기·뱀·상어는
  "지금 어느 쪽을 보고 있나"가 절반인데, 방향은 `d` 라는 정수 하나에만 들어 있어서
  변수 상자에 숫자로만 떴다. 판정은 **예측력**으로 한다 (격자 커서와 같은 방법) —
  커서가 실제로 움직인 만큼을 `dr[d]`, `dc[d]` 가 맞히는가.
  어느 쪽이 dr 이고 어느 쪽이 dc 인지도 이걸로 갈린다 (이름은 못 믿는다).
  **BFS 는 못 맞히고, 그게 맞다** — 네 방향을 매번 다 훑는 코드에 "바라보는 방향"은
  없으니 화살표를 그리면 거짓말이다. 화살표 글자(→)와 이모지는 이 환경에서
  네모로 깨지므로 CSS 테두리로 삼각형을 그려 돌린다
- **좌표 집합은 칩이 아니라 격자에 켠다.** 파이썬 격자 BFS 의 표준 꼴은
  `visited = set()` 에 `(r, c)` 튜플을 넣는 것인데, 지금까지 칩 목록으로만 보이고
  **정작 격자에는 아무 표시가 없었다.** 칩에 적힌 좌표를 눈으로 격자에 옮겨 그려야
  "어디를 이미 갔나"를 알 수 있었다. 원소가 전부 그 격자 안의 (행, 열) 이면
  그 칸을 켜고, 칩 목록과 변수 상자에서는 뺀다 (같은 말을 두 번 하지 않는다)
- **그래프 노드를 색칠한다.** 이분 그래프 판별·그래프 컬러링은 `color[v]` 에 답이
  들어 있는데, 지금까지 그 배열은 옆에 막대로만 그려졌다. 어느 노드가 무슨 색인지는
  막대의 인덱스를 눈으로 그래프에 옮겨야 알 수 있었다.
  **가르는 신호는 "색은 한 번 정하면 안 바뀐다"** 는 것이다. 이 조건이 없으면
  위상정렬의 `indeg`(줄었다 늘었다)와 서브트리 `size`(쌓임)가 죄다 색으로 잡힌다 —
  둘 다 값이 몇 개 안 되고 0 으로 시작하니까
- **집합 = 칩.** `visited = {1, 2, 3}` 을 늘어놓고 방금 들어온 것을 짚어준다.
  그래프의 방문 표시로 이미 보이면 두 번 안 그린다
- **트라이 = 트리.** 딕셔너리 안에 딕셔너리가 들어가면 그건 트리다. 노드는 **경로**로
  식별해서 자라나도 같은 노드가 같은 자리에 남는다. 트리 안을 돌아다니는 커서
  변수(`node = node[ch]`)도 같이 잡히는데, **크기로 고르면 안 된다** — 커서는 여러
  서브트리를 훑어서 합집합이 오히려 더 크다. 진짜 트리는 마지막에도 자기가 가졌던
  걸 다 갖고 있다는 점(보존율)으로 가른다
- **스택 / 큐 = 상자 줄.** 리스트가 값을 담는 그릇이 아니라 쌓았다 빼는 용도면
  막대는 무의미하다(괄호 검사의 stack 은 1 만 잔뜩 들어 있다). 넣는 쪽은 둘 다 뒤라
  구별이 안 되고 **빼는 쪽**으로 갈린다 — 뒤에서 빼면 스택, 앞에서 빼면 큐.
  한 번에 한 개씩 빠져야 한다 (여러 개가 한꺼번에 사라지는 건 함수 재호출로
  지역 리스트가 초기화된 것이다). 값이 다 같아서 못 가릴 때는 `deque` 여부로 정한다.
  **넣는 걸 요구하면 안 된다** — 요세푸스처럼 `deque(range(n))` 로 한 번 채우고
  빼기만 하는 큐가 통째로 빠진다. 쌓기만 하는 결과 리스트는 빼는 게 없어서 알아서 걸러진다
- **구간 = 가로 막대.** `[(1,4), (3,5), ...]` 처럼 (시작, 끝) 쌍이 늘어선 자료.
  **모든 행에서 앞 <= 뒤** 여야 하고, **폭이 0 인 행이 20% 를 넘으면 안 된다.**
  하노이 이동 `(3,2)` 는 뒤집혀서, 좌표 `[(0,0), (3,4), (1,1)]` 은 폭 0 이 많아서 걸러진다.
  회의실 배정에서 정렬이 일어나면 막대가 자리를 옮긴다.
  **행 수가 변하면 구간이 아니다** — 회의 N개를 받아 훑을 뿐 도중에 회의를 만들지
  않는다. 백트래킹의 `result` 가 답을 찾을 때마다 한 줄씩 늘어나며 구간으로 잡혔다.
  **그래프가 이미 잡혔고 숫자가 전부 그 그래프의 노드면 간선 리스트다** —
  `edges = [(0,2),(1,2),...]` 를 가로 막대로 눕히면 `(2,3)` 을 "2에서 3까지의 시간"으로
  읽게 만들어서 오히려 틀리게 가르친다
- **격자 위 현재 위치 = 칸 테두리.** `r`, `c` 를 이름으로 찾으면 `nr`/`nc`, `x`/`y` 로
  갈아입을 때마다 깨진다. **예측력으로** 찾는다 — 어떤 (a, b) 쌍이 가리킨 칸이
  실제로 바뀐 칸과 일치하는 횟수를 세서 가장 잘 맞히는 쌍을 고른다.
  안 변하는 격자는 값으로 못 찾으니 두 가지를 이 **순서로** 시도한다.
  **1) 소스에 적힌 첨자** — 코드에 `A[i][k]` 라고 쓰여 있으면 그게 답이다.
  **2) 같은 크기 격자의 커서 빌리기** — 미로 벽 지도처럼 단서가 아예 없을 때만.
  순서를 바꾸면 행렬 곱셈이 틀린다: `C[i][j] += A[i][k] * B[k][j]` 인데
  A 와 B 가 C 의 (i, j) 를 빌려 써서 엉뚱한 칸에 테두리가 쳐졌다.
  A 는 i 행을, B 는 k 행을 보고 있는데도
- **클래스로 만든 객체 = 노드-링크 그림.** `tracer` 가 프레임마다 `objs` 표를 남기고
  본문에는 `{__ref__: 번호}` 만 둔다. 그 참조가 곧 간선이다. 순환(`prev`, `parent`)이
  있어도 표 구조라 안전하다. 자식이 하나뿐이면 가로 한 줄(연결리스트),
  트리면 계층, 나머지는 원형. 간선에는 필드 이름(`next`/`left`/`right`)을 쓴다.
  **배치 기준은 전체 프레임의 합집합** — `head.next.next.next = Node(4)` 처럼
  만들고 잇는 사이에는 "노드는 다 있는데 마지막 간선이 없는" 프레임이 있어서,
  그걸 기준으로 잡으면 마지막 화살표를 영영 안 그린다
- **힙 = 완전이진트리.** `heapq` 가 쓰는 리스트는 사실 트리다. 판정은 네 가지를 다
  만족할 때만: 힙 성질이 한쪽으로 일관되게 성립 + 정렬 안 된 순간이 있다
  (늘 정렬이면 그냥 정렬된 배열) + 길이가 변한다 + 값이 변한다
- **부모 포인터 배열 = 화살표.** `parent = [0,1,1,1,3,1]` 은 값이 아니라 "누가 누구를
  가리키나"가 전부라 막대 높이에 의미가 없다. 칸을 한 줄로 놓고 `i -> parent[i]` 를
  위쪽 곡선으로 그린다. 판정에서 결정적인 조건은 **처음에 모든 칸이 자기를 가리킨다**
  (`parent = list(range(n))`)는 것이다. 이게 없으면 위상정렬의 `indeg` 나 KMP 의
  실패함수처럼 "값이 전부 유효한 인덱스"인 배열이 죄다 부모 배열로 잡힌다.
  **길이 3 이상일 때만 그 조건이 뜻이 있고, 자라나는 리스트는 부모 배열이 아니다** —
  큰 수 덧셈의 `digits` 가 `[0]` 한 칸으로 시작해서 그 조건을 거저 통과했다
- **패턴은 텍스트에 맞춰 민다 (KMP).** 텍스트와 패턴을 따로 그리면
  "지금 어디에 맞춰보고 있나"가 안 보인다. 그게 KMP 의 전부인데.
  짧은 쪽을 `i - j` 칸만큼 밀어 겹쳐 놓으면 어긋난 자리에서 패턴이 얼마나
  미끄러지는지가 바로 보인다. 근거: 긴 문자열과 짧은 문자열에 각각 포인터가 있고
  (긴 쪽 - 짧은 쪽)이 음수가 안 되고 여러 값을 가진다.
  **칸 폭을 양쪽 같게 맞춰야** 세로가 안 어긋난다 (확인은 눈이 아니라
  `getBoundingClientRect().left` 비교로)
- **표 위 자취 = 역추적 경로.** DP 역추적(LCS)은 "표를 거슬러 올라간 경로"가
  답 그 자체인데 커서 한 칸만 보이면 그 경로가 안 보인다. 지나온 12칸을 남긴다.
  재생하며 쌓지 않고 **미리 계산해 둔 자취를 되짚는다** — 안 그러면 스크럽으로
  되감았을 때 자취가 거짓말을 한다
- **경유지 축 = 행/열 띠 (플로이드 워셜).** `d[i][k] + d[k][j]` 처럼 같은 격자를
  **다른 축으로** 뒤지는 변수가 있으면 그 행과 열을 통째로 칠한다.
  판정의 핵심은 **양쪽 축에 다 쓰였는가** — `d[k][j]` 와 `d[i][k]` 가 둘 다 있어야 한다.
  한쪽만 보면 미로의 `dist[r][c]` 의 `r` 이 걸려서 격자 문제마다 엉뚱한 행이 칠해진다
- **문자열 = 칸.** 문자열, 또는 12자 이하 문자열의 리스트(`list(s)`, 단어 배열).
  2~64칸. 문자열 문제는 "몇 번째 글자를 보고 있나"가 전부라 칸으로 그려야 읽힌다
- **포인터 = 값이 변하는 정수 변수.** 안 변하면 `n = len(arr)` 같은 상수라 포인터가 아니다.
  붙는 자리는 **코드가 정한다** — 소스에 `a[i]`, `b[j]` 라고 쓰여 있으면 그게 답이다.
  값만으로는 두 배열을 훑는 `i`, `j` 를 못 가른다 (둘 다 양쪽 범위에 들어맞는다).
  코드에서 못 찾으면 프레임마다 길이 안에 들어오는지 보고 여유가 가장 적은 열을 고른다.
  배열만이 아니라 **문자열도 후보다** — 팰린드롬·투포인터는 문자열 위에서 돈다
- **지금 보고 있는 구간 = 바닥 칠하기.** 투 포인터·슬라이딩 윈도우·이분탐색·구간합은
  "배열 전체"가 아니라 **지금 살아 있는 구간**에 대한 이야기다. 포인터 칩만으로는
  "어디부터 어디까지"가 눈에 안 들어와서, 두 포인터 사이를 칠한다 (막대·글자칸 공통).
  **값만으로 판정하면 안 된다** — 위상정렬의 `indeg[b]`/`indeg[nx]` 나 다익스트라의
  `dist[u]`/`dist[v]` 도 값으로는 완벽한 "구간"이라 죄다 칠해졌다. 근거는 코드에 있다:
  둘을 견주거나(`while lo < hi`) 한쪽이 다른 쪽을 한계로 삼을 때(`for j in range(i)`)만
  구간으로 본다 (`relatedPairs`)
- **구간(수직선) = 이분탐색.** 배열이 없는 코드를 위한 것. 아래 참고
- **그래프 = 인접구조.** dict of list, 또는 행 길이가 들쭉날쭉한 2차원 리스트.
  **값이 그 리스트의 인덱스여야 한다** (딕셔너리 쪽에서 "키 집합에 있는가"로 가리는
  것과 같은 조건). 이게 없으면 기수 정렬의 `bucket = [[170, 90], [45], ...]` 이
  그래프가 된다 — 170번 노드가 생긴다. 간선도 셋은 있어야 한다
  (`bucket` 이 어쩌다 `[[2], [], ...]` 가 된 순간에 "노드 10개 간선 1개 그래프"로 잡혔다).
  **단 "지금 어느 간선이 살아 있나"를 읽을 때는 이 조건을 푼다** — 만들어지는 중이라
  간선이 하나뿐인 프레임도 읽어야 첫 간선이 이어지는 순간이 화면에 보인다
  행 길이가 균일하면 DP 표로 본다. 노드 3~40개
  - 방문 표시: 노드 번호를 담는 set, 또는 노드 수만큼 긴 bool 리스트
  - 현재 노드: 노드 번호 범위 안에서 움직이는 정수 (최대 3개)
  - 배치는 세 가지. **간선이 노드-1 개이고 다 이어져 있으면 트리**라 계층 배치,
    **방향이 있고 순환이 없으면(DAG) 층 배치**, 나머지는 원형.
    위상정렬을 원형으로 그리면 "무엇이 무엇보다 먼저인가"가 아예 안 보인다 —
    원은 시작도 끝도 없으니까. 층 = 그 노드까지 오는 **가장 긴 경로의 길이**라,
    같은 층끼리는 서로 앞뒤가 없다는 뜻이 된다. 층이 곧 답의 설명이다.
    **간선 리스트에서 만든 그래프(크루스칼)는 층으로 안 눕힌다** — (a, b) 의 방향이
    아무 뜻이 없어서, 눕히면 "a 가 b 보다 먼저"라는 코드에 없는 말을 지어내게 된다.
    뿌리는 들어오는 간선이 없는 노드(자식만 나열한 구조), 없으면 첫 노드
- **값 변화(꺾은선) = 변하는 숫자 스칼라.** 크기가 20배 안쪽인 것끼리 한 그림에 묶는다
  (`cnt_a` 7 과 `p` 1000 을 같이 그리면 둘 다 안 보인다)
- **가중치 인접리스트도 받는다.** `{1: [(2, 7), ...]}` 에서 어느 쪽이 이웃인지는
  "키 집합에 있는가"로 가린다. 가중치는 보통 노드 번호 범위를 벗어나서 갈린다
- **INF 센티넬은 눈금에서 뺀다.** `dist = [10**9] * n` 이 있으면 나머지 막대가
  전부 바닥에 깔린다. 하위 25% 값의 100배를 넘으면 센티넬로 보고, 그 막대만
  빗금 + `∞` 로 표시한다 (`robustMax`)
- **2열 구조는 표가 아닐 때가 많다.** 행 수가 변하거나 거의 모든 프레임에 안 나오면
  `pq`·`moves` 같은 "쌍을 담는 그릇"으로 보고 표에서 뺀다
- **꺾은선은 쌓이는 값만.** 방향이 한쪽으로 8할 이상 쏠릴 때만 그린다.
  격자 문제의 `dr`/`dc`/`nr`/`nc` 처럼 오르내리기만 하는 임시변수를 걸러낸다.
  함수 안에서만 사는 변수도 뺀다 — 호출마다 초기화돼 톱니가 된다
- **호출 스택은 깊이에 따라 자리가 달라진다.** 깊이 2 이상이면 재귀라 맨 위,
  깊이 1 뿐이면 생성자나 헬퍼를 한 번 부른 것이라 자료구조 뒤로 민다.
  대부분의 프레임에서 비어 있는 블록이 화면 위쪽을 차지하면 안 된다
- **방향 벡터는 안 그린다.** `dr = [0,1,0,-1]`, `dc = [1,0,-1,0]` 는 격자 문제마다
  따라 나오는 상수 표다. 한 번도 안 변하고, 값이 -1~1 이고, 길어야 여덟 칸.
  막대로 그려도 재생 내내 가만히 있어서 화면만 먹는다
- **같은 변수가 블록 두 개로 나오면 안 된다.** 괄호 검사의 `stack = []` 에 문자를 넣으면
  "글자 칸"과 "스택" 두 블록이 같은 이름으로 떴다. 이미 그림을 받은 변수는 글자로
  또 그리지 않는다 (회귀 확인에 이름 중복 검사를 넣어뒀다)
- **화면 순서**: 객체 그림·재귀 호출 스택·그래프가 있으면 늘 맨 위 → 나머지는 변화량 순 → 꺾은선은 맨 아래.
  BFS 에서 `order` 리스트가 더 자주 변한다고 그래프를 밀어내면 안 된다.
  **입력에서 바로 온 배열**(`x = ... input(...)`)은 "문제가 준 데이터"라 위로 올린다 —
  중력 문제의 `heights`(스카이라인)가 변화량이 적다고 맨 아래로 밀리면 안 된다

- **자리바꿈은 따로 표시한다.** 직전 프레임과 딱 두 칸이 다르고 그 값이 서로
  맞바뀌었으면 swap 으로 보고 주황색으로 칠한다. 정렬 코드에서 "바꿨다"와
  "덮어썼다"는 의미가 전혀 다른데 지금까지 똑같이 반짝였다
- **정렬 key 람다·컴프리헨션은 호출로 세지 않는다.** 안 그러면
  `meet.sort(key=lambda x: x[1])` 한 줄에 호출 스택 블록이 뜬다

이미 다른 방식으로 보이는 건 두 번 그리지 않는다:
- 배열 위 포인터로 그려지는 짝이면 수직선을 안 그린다
- 배열 위 포인터인 값은 꺾은선에서 뺀다 (`bubble` 의 `i`, `j`)

### 구간 탐지 (`findRanges`)

이분탐색·파라메트릭 서치는 배열 없이 숫자 구간만으로 돈다. 그래서 따로 찾는다.
`la/ra`, `lb/rb`, `lo/hi`, `left/right` … 이름 변형이 끝이 없어서 **이름이 아니라
의미로** 찾는다. 네 조건을 다 만족해야 한다.

1. 거의 항상 `lo <= hi`
2. 폭이 계속 줄어든다 (커지는 경우는 테스트케이스 초기화라 조금 봐준다)
3. **폭이 최대치의 20% 아래까지 수렴한다** — 이게 가장 중요한 조건이다
4. **그 구간 한가운데 앉아 있는 세 번째 변수(mid)가 반드시 있다.** 그게 이분탐색의
   정의다. 이름만 짝인 걸 받아줬더니 위상정렬의 `cur`, `u` 가 탐색 구간으로 잡혔다

여기에 조건이 하나 더 붙는다. **코드가 둘을 견주고 있어야 한다**(`while lo <= hi`).
값만 보면 파라메트릭 서치의 `answer`(= mid 를 받아 두는 답 변수)가 경계로 잡힌다 —
answer 도 구간 안에서 수렴하니까. 구간 칠하기에 쓴 것과 같은 근거다.
그 대신 "mid 가 구간 안에 있는 비율" 조건은 0.9 에서 0.7 로 풀었다.
mid 는 경계가 갱신된 뒤에도 옛 값을 들고 있어서 프레임 단위로 보면 구간 밖에 있는
순간이 꽤 되고, 0.9 를 요구하면 파라메트릭 서치가 통째로 빠진다.

3번이 핵심인 이유: 한가운데 점수만으로는 **못 가른다.** 실측했더니 진짜
`lb..rb`(0.294)와 우연히 걸린 `i..pa`(0.291)가 사실상 같았다. 반면 폭 수렴
비율은 진짜 0.005~0.016 vs 우연 0.333~0.992 로 깨끗하게 갈렸다.
**탐색 구간은 결국 한 점으로 수렴한다**는 게 진짜 서명이다.

주의할 함정 둘:
- **경계가 한 번도 안 움직일 수 있다.** 답이 계속 아래쪽 절반이면 `lo` 는 1 그대로다.
  "안 변하면 경계가 아니다"로 걸렀다가 `la..ra` 를 통째로 놓쳤다
- **한 글자 이름끼리는 이름 유사도가 무조건 참이 된다** (`slice(1)` 이 둘 다 `""`).
  `i` 와 `p` 가 짝으로 잡혔다. `a.length > 1` 이 필요하다

배열 위 포인터로 이미 그려지는 짝이면 수직선은 안 그린다 (군더더기).

왼쪽 줄 번호를 누르면 그 줄까지만 돌린다. 그 아래 코드는 어둡게 덮이고 실행되지 않는다.

`tracer.py` 의 `_truncate()` 가 소스를 그 줄까지 자른다. **블록 한가운데를 자르면
문법이 깨지므로** (`for i in ...:` 바로 다음에서 자르는 경우) `pass` 를 붙여 보고,
그래도 안 되면 컴파일될 때까지 한 줄씩 물러난 뒤 실제로 어디까지 돌았는지 알려준다.
앞부분 줄 번호는 그대로 두므로 코드 하이라이트가 안 어긋난다.
덧붙인 `pass` 는 기록에서 뺀다 (없는 줄이 하이라이트되면 안 되니까).

## 아직 안 된 것

- **swap 이 미끄러지지는 않는다.** 자리바꿈은 주황색으로 구별해 표시하지만, 두 막대가
  서로 지나가는 애니메이션은 아직이다. 그러려면 인덱스가 아니라 원소 정체성으로
  DOM 을 키잉해야 하는데, 중복 값이 있으면 정체성을 못 정한다
- **안 움직인 포인터는 안 보인다.** `binsearch` 예제의 `hi` 는 8 에서 한 번도 안 움직여서
  칩이 안 뜬다. 이 규칙을 풀면 `target = 14` 같은 상수가 14번 칸에 포인터인 척 붙는다
- **트리가 아닌 그래프는 원형 배치다.** 겹치지 않고 프레임마다 안 흔들리고 어떤
  그래프든 실패하지 않지만, 간선이 많으면 실타래처럼 보인다
- **객체는 한 프레임에 200개까지만 따라간다.** 그보다 크면 repr 로 떨어진다
- **간선 리스트는 근거가 있을 때만 그린다.** `[(1,4), (3,5)]` 이 간선인지 구간인지
  좌표인지는 **데이터만으로 구별할 수 없다.** 억지로 그래프로 그리면 회의실 예약이
  12개 노드짜리 그래프가 된다. 그래서 오래 안 그렸는데, 근거 셋이 생겼다:
  같은 코드에 **유니온 파인드 부모 배열**이 있으면 간선(크루스칼),
  소스가 **쌍을 풀어 첨자로 쓰면**(`for u, v, w in edges:` 다음에 `dist[u]`) 역시 간선
  (벨만-포드 — 부모 배열이 없어서 표로만 나오던 걸 이걸로 잡았다),
  두 성분을 따로 꺼내 쓰면 **좌표**(산점도),
  이미 그래프가 잡혀 있고 숫자가 전부 그 노드면 **간선 리스트라 구간에서 뺀다**.
  셋 다 아니면 여전히 안 그린다
- **N-Queens 판을 안 그린다.** `cols[r] = c` 는 사실 n x n 판인데 막대로 그린다.
  판으로 그리려면 "길이 n, 값이 전부 0..n-1 인 정수 배열"을 판으로 봐야 하는데,
  그 조건에 `out`(계수 정렬), `dp`(LIS), `fail`(KMP)이 죄다 걸린다. 실제로 세어 봤다.
  **판정할 신호가 없으면 안 그리는 게 맞다** — 오판은 없는 것보다 나쁘다
- **스텝 상한 20000.** N퀸(n=6)이 9,894 스텝으로 완주한다(207ms). n=7 부터는 잘린다
- **경로 압축을 한 유니온 파인드는 화살이 뚝뚝 끊겨 보인다.** 한 번에 여러 칸의
  부모가 바뀌므로 중간 과정이 안 보인다 (곡선 자체는 정확하다)

## 지금 실행하려는 줄에 값을 넣어 보여준다

재생 프레임의 3분의 1은 아무것도 안 바뀐다 — 조건을 재거나, 이제 막 어떤 줄을
실행하려는 참이다. 예전엔 그 줄의 **원문만 되풀이**했다. 코드 창을 다시 읽으라는 소리다.

```
9줄  ·  count[w] = 1                    →   9줄  ·  count["fox"] = 1
9줄  ·  mid = (lo + hi) // 2            →   9줄  ·  mid = (0 + 8) // 2
9줄  ·  d[i][j] = d[i][k] + d[k][j]     →   9줄  ·  d[2][1] = d[2][3] + d[3][1]
20줄 ·  visited.add((nr, nc))           →   20줄 ·  visited.add((0, 1))
9줄  ·  if s[left] != s[right]:         →   9줄  ·  if s[3] != s[3]:   →  거짓
```

값을 넣는 자리는 **뜻이 안 흔들리는 곳만**이다: 첨자 안, `range(...)` 안,
대입의 **오른쪽**(왼쪽은 이제 정해질 이름이라 절대 안 건드린다), 그리고 대입이 없는
줄의 괄호 안. 리스트·딕셔너리 값은 안 넣는다 (한 줄에 배열이 통째로 들어오면 못 읽는다).
78자를 넘으면 원문으로 되돌린다 — 띠 한 줄에 안 들어가면 아무것도 못 읽는다.

**조건 줄에는 결과를 붙인다.** 조건 줄 다음에 실행된 줄이 그 몸통 안(더 깊은
들여쓰기)이면 참, 아니면 거짓. 파이썬은 들여쓰기가 곧 블록이라 이게 그대로 성립한다.
"왜 이 줄로 갔나"의 답이 바로 그거다. 프레임을 앞뒤로 봐야 하므로 재생 중이 아니라
`analyze` 에서 미리 다 계산해 둔다 (되감아도 맞아야 하니까).

이렇게 해서 맹탕 서술이 **33% → 8%** 로 줄었다.

## 방금 무슨 일이 있었나 (설명 줄)

그림은 "지금 상태"를 보여준다. 그런데 그것만으로는 **뭐가 어디서 적용됐는지**가
안 읽힌다. 예쁘지만 따라가기 어려운 트레이드오프가 생긴다.

그래서 화면 맨 위에 한 줄을 고정으로 둔다.

```
19줄  ·  def_idx[5]  -1 → 0
7줄   ·  arr[0] ↔ arr[1]  (5, 3 자리 바꿈)
11줄  ·  find(x=3) 호출
7줄   ·  find 끝  →  1 반환
5줄   ·  while parent[x] != x:        ← 아무것도 안 바뀐 프레임
```

두 가지 규칙이 핵심이다.

1. **원인이 된 줄 번호를 앞에 쓴다.** 효과는 그 줄을 실행한 **다음** 프레임에
   보이므로, 직전 프레임의 줄 번호를 붙여야 "어느 줄이 이걸 했는지"가 연결된다
2. **바뀐 게 없으면 지금 보고 있는 줄의 원문을 쓴다.** 조건 검사처럼 아무것도
   안 바뀌는 프레임에서 빈 줄이 뜨면 고장 난 것처럼 보인다

여러 개가 동시에 바뀌면 구조(배열·표)를 스칼라보다 먼저 고르고 나머지는 개수만
알린다. 그리고 **바뀐 변수의 블록에 주황 표시**를 붙여, 여러 그림 중 어느 것을
봐야 하는지 바로 보이게 한다.

## 지금 몇 번째 단계인가 (주석을 단계로)

설명을 지어낼 필요가 없다. **사용자가 이미 코드에 써 놨다.**

```python
# 가장 높은 블럭 찾기
...
# 각 층 블록 개수, 첫 블록 인덱스
...
```

`#` 주석 한 줄이 그 아래 구역의 제목이 된다. 재생하면서 초록 띠에
`4/5단계   각 층 블록 개수, 첫 블록 인덱스` 를 띄우면, 그림이 **무엇을 하는 중인지**가
붙는다. 그 아래 회색 띠(방금 무슨 일이 있었나)와 짝을 이룬다 — 위는 "왜",
아래는 "무엇".

- 주석이 **둘 미만이면 아무것도 안 만든다.** 하나뿐인 걸 "단계"라고 부를 수 없다
- **코드보다 먼저 나온 주석은 파일 제목이지 단계가 아니다.** `# gravity` 가
  1/6단계로 세어지고 있었다
- 억지로 지어내지 않는다. 주석이 없는 코드에서는 이 띠가 아예 안 뜬다

## 주석을 그림에도 단다

단계 띠(초록)는 "지금 어느 대목인가"를 말해 준다. 그런데 그림이 여럿일 때
**어느 그림이 뭔지**는 여전히 안 붙어 있었다. 사람은 선언 옆에 그 답을 이미 써 놓는다.

```python
# 각 층 블록 갯수
length = []
def_idx = []          # 기존 블록 인덱스
result = 0            # 최대 낙차
```

```
length  · 각 층 블록 갯수
def_idx · 기존 블록 인덱스
값 변화 · 최대 낙차 · 시간에 따른 result
```

붙이는 규칙은 둘뿐이다.
- **줄 끝 주석**은 그 줄이 만든 변수의 것
- **홀로 선 주석**은 바로 다음 코드 줄이 만든 변수의 것 (빈 줄은 건너뛴다)

주의할 점 셋:
- **다음 코드 줄이 대입이 아니면 아무 데도 안 붙인다.** `# 최대 낙차 구하기` 다음이
  `for idx in range(n):` 이면 그건 그 대목의 제목이지 어느 값의 설명이 아니다
  (그건 단계 띠가 맡는다)
- **코드보다 먼저 나온 주석은 파일 제목이다.** `# 세그먼트 트리 — 배열 하나가
  사실은 트리다` 가 `arr` 의 설명으로 붙었다. 단계 띠와 같은 함정
- **문자열 안의 `#` 은 주석이 아니다.** `print(f'#{tc} {ans}')` 는 SWEA 코드에 늘 있다

주석이 있으면 **내가 유추한 역할 꼬리표는 안 붙인다.** `length · 각 층 블록 갯수 ·
채우는 표` 는 같은 자리를 두 번 설명하는 셈이고 제목만 길어진다. 사용자가 쓴 말이 이긴다.
**무슨 그림으로 그렸는지(`0/1 지도` 등)는 판정 검증용이라 늘 남긴다.**

## 지금 없는 값은 접는다

함수 밖으로 나오면 지역변수는 사라진다. 예전엔 그 블록을 **흐리게만** 했는데,
흐린 채로 자리는 그대로 차지했다. 병합정렬은 함수 안 지역변수가 넷이라
대부분의 프레임에서 빈 막대칸 넷이 화면을 700px 씩 먹었고, 정작 지금 살아 있는 게
뭔지는 안 보였다.

지금은 제목만 남기고 접는다 — `left · 지금 없음`.
**감추는 게 아니라 "지금 이 변수는 없다"를 그리는 것이다.** 함수 밖으로 나오면
지역변수가 사라진다는 걸 눈으로 보게 된다. 병합정렬 시작 프레임이 1693px → **681px**,
호출 트리 전체가 한 화면에 들어온다.

깜빡이지 않는지도 쟀다 — 접힘이 바뀌는 프레임은 1~19% 다 (병합정렬이 19%로 가장 잦은데,
재귀 함수의 지역변수가 실제로 그만큼 들락거린다).

## 화면 밖으로 나간 그림은 짚어봐야 안 보인다

바뀐 블록에 주황 표시를 붙여도, 그 블록이 화면 밖이면 소용이 없다.
방금 바뀐 블록이 보이지 않으면 **필요한 만큼만** 굴린다. 이미 보이는 블록이면
아무것도 안 한다 — 안 그러면 재생 내내 화면이 덜컹거린다 (실측: 129프레임 중 19번).

**사용자가 직접 굴렸으면 4초간 손을 뗀다.** 뭔가 보려고 내렸는데 다음 프레임이
도로 끌어올리면 아무것도 못 본다.

## 이름만 달린 블록을 없앤다

감사해 보니 **설명 없는 블록이 159개**였다 — 절반 넘는 그림이 이름만 달고 있었다.
그런데 상당수는 코드에 답이 적혀 있었다.

- `arr = [5, 3, 8, 1]` → **주어진 값** (들여쓰기 없는 줄의 리터럴 + 안 변함)
- `def merge_sort(a):` → **받은 값** (그 함수가 받은 인자)
- `s = s[1:-1]` → **줄어드는 중** (글자가 잘려 나가기만 한다)

그리고 더 큰 구멍이 있었다. **역할 판정이 숫자만 보고 있었다.** 문자열·단어 배열은
`findRoles` 의 통계에 아예 안 들어가서 역할이 붙을 수가 없었고, 붙였더라도
`analyze` 가 막대·표에만 역할을 달고 글자 칸은 건너뛰고 있었다. 둘 다 고쳤다.

159 → 116 → 56 → 23 → **0개**. 마지막 23개도 하나씩 들여다보니 대부분 붙일 말이 있었다.

- **자리 바꾸는 중** — 원소 구성은 그대로인데 순서만 바뀐다. 뒤집기·회전·섞기.
  "정렬 중"과 같은 종류의 움직임인데 끝에 정렬돼 있지 않을 뿐이다
  (`dice`, `gear` 의 톱니 회전, `strrev` 의 뒤집기)
- **고쳐 나가는 표** — 크기는 그대로인데 값이 계속 갈린다. 쌓지도 채우지도 않고
  제자리에서 고쳐 나간다는 것 자체가 알려줄 만한 사실이다 (플로이드의 거리표)
- **주어진 값을 넓혔다** — 리터럴만이 아니라 `words = text.split()` 처럼 계산해서
  만들고 그 뒤로 안 변하는 것도 알고리즘 입장에서는 "주어진 것"이다
- **길이가 0/1 로 떨어지는 건 다시 시작한 것**이지 빼낸 게 아니다.
  함수가 다시 불려 지역 리스트가 초기화되는 게 그 모양인데, 그걸 "줄어듦"으로 세서
  병합정렬의 `out` 과 부분집합 순회의 `cur` 이 역할을 못 받고 있었다
- **참/거짓 표와 문자열도 역할 판정에 넣었다** — 숫자만 보고 있었다

### 붙인 말이 맞는지 눈으로 대조했다

"무설명 0개"는 **아무 말이나 붙여도** 달성된다. 틀린 설명은 없느니만 못하므로
22개 코드의 라벨을 하나씩 코드와 맞춰 봤고, 둘이 틀렸다.

- `strrev s` 가 "고쳐 나가는 표"로 나왔다. 원인은 `sortedKey` 가 숫자 비교(`x - y`)만
  써서 **글자에서는 NaN 이 나와 정렬이 제멋대로**가 된 것. 구성이 같은지 못 가려서
  뒤집기를 "값을 갈아끼웠다"로 읽었다 → 자리 바꾸는 중
- `palindp pal` 도 "고쳐 나가는 표"였다. 참/거짓 표는 값이 두 가지뿐이라
  "값의 가짓수가 늘었나" 조건에 절대 안 걸린다. **처음에 완전히 한 값이었다가
  그게 깨졌으면 채우는 중**이라는 조건을 더했다 → 채우는 표

## 이 그림은 무슨 역할인가 (블록 제목)

그림만 덩그러니 있으면 "이게 뭐하는 배열이었지"를 매번 코드로 돌아가 다시 읽어야
한다. 값이 **어떻게 움직였는지만** 보고 역할을 한 마디로 붙인다. 이름은 안 본다
(`dp` 라고 이름 붙였다고 DP 표인 게 아니다).

| 제목 | 근거 |
|---|---|
| `arr · 정렬 중` | 원소 구성은 그대로인데 순서만 바뀌고, 끝에 가면 정렬돼 있다 |
| `heights · 입력값` | `input()` 으로 읽었고 그 뒤로 한 번도 안 변한다 |
| `dp · 채우는 표` | 처음엔 거의 한 값이었다가 값이 들어찬다 |
| `order · 쌓는 곳` | 길이가 늘기만 한다 |

어느 쪽도 아니면 **아무 말도 안 붙인다.** 억지로 이름 붙이면 더 헷갈린다.
`0` 만 특별 취급하면 안 된다 — 다익스트라의 `dist = [INF] * n` 이나 LIS 의
`dp = [1] * len(a)` 를 놓친다. "처음엔 한 값, 나중엔 여러 값"이 진짜 서명이다.

## 함수를 작게 유지하는 이유

파일이 길어지는 건 문제가 아니다 (전부 합쳐 212KB, 브라우저가 눈 깜짝할 새에 읽는다).
**함수가 길어지는 게 문제다.** 한때 `update()` 하나가 702줄, `analyze()` 가 525줄이라
둘이 판정·그리기 코드의 35% 였다. 그러면 "이 부분"을 가리킬 앵커가 흐려지고,
줄 범위로 자르다가 **옆 함수를 통째로 날린 적이 있다.**

지금은 이렇게 나뉘어 있다.

- `update()` 는 **부르는 순서만** 남기고, 그림 종류마다 `refreshXxx()` 하나씩 (26개).
  새 유형을 넣으면 `REFRESH` 목록에 한 줄, 함수 하나가 는다
- 설명 층(주석·단계·역할·구간)은 `viz-explain.js` 로 나갔다. 판정과 독립이라
  거길 고쳐도 **어떤 그림을 그릴지는 안 바뀐다**
- `analyze()` 의 통계 수집 첫 훑기는 `collectStats()` 로 뺐다

**`analyze()` 의 나머지(440줄)는 일부러 안 쪼갠다.** 거기 있는 건 "어떤 순서로
판정하고 겹치면 누가 이기나"인데, **그 순서 자체가 로직**이다. 인접 행렬을 격자보다
먼저 볼지, 부모 배열이 세그먼트 트리를 이기는지 — 파일 여러 개로 흩으면 오히려 못 읽는다.

### 리팩터할 때는 지문을 뜬다

"문법 통과"나 "문제 0개"는 **동작이 같다는 근거가 못 된다.**
`dev/fingerprint.js` 가 예제마다 프레임 다섯 군데를 그린 뒤 무대 DOM 전체를 해시하고,
`dev/baseline.txt` 와 한 글자씩 대조한다.

```js
for (const f of ["/dev/cases.js", "/dev/fingerprint.js"])
  (0, eval)(await (await fetch(f, {cache: "no-store"})).text());
await COMPARE([SAMPLES, DEVCASES]);      // "지문 91개 전부 같음" 이 나와야 한다
```

**동작을 일부러 바꿨을 때만** 새 지문으로 덮어쓴다. 손으로 옮겨 적지 말고
`await SAVE_BASELINE([SAMPLES, DEVCASES])` 를 부르면 개발 서버가 받아 쓴다
(`serve.py` 가 `/dev/baseline.txt` 로 오는 POST 하나만 받는다. 127.0.0.1 전용).

지문은 **의도한 변화만 짚어 준다.** 세그먼트 트리에 커서를 붙였을 때 나온 결과가 이렇다.

```
달라짐 segtree | 전 ... 261bca44 24278458 064d2e26 f572777f 95bb8079
               | 후 ... da9b2d37 e2b8ae4b b1c2f935 f572777f 95bb8079
```

한 케이스의 앞 세 프레임만 달라졌고 나머지 100개는 한 글자도 안 바뀌었다 —
"의도한 것만 바뀌었다"는 걸 이렇게 확인한다.

## 잘 읽히는가 — 품질 감사 (`dev/audit.js`)

회귀 검사는 "터지지 않는가"만 본다. 그림이 **쓸모 있는지**는 따로 재야 한다.
재는 잣대가 없으면 "좋아졌다"는 말은 느낌일 뿐이다.

```js
(0, eval)(await (await fetch("/dev/audit.js", {cache: "no-store"})).text());
AUDIT_REPORT([SAMPLES, DEVCASES]);
```

| 잣대 | 뜻 | 처음 | 지금 |
|---|---|---:|---:|
| 무설명 | 이름만 있고 주석도 역할도 없는 블록 | 159개 | **0개** |
| 안변함 | 안 변하는데 뭔지도 안 알려주는 블록 | 87개 | **0개** |
| 맹탕서술 | 소스 원문을 그대로 되풀이한 프레임 | 33% | **8%** |
| 최대 높이 | 한 화면에 안 들어오는 정도 | 1933px | 1777px |

무엇을 고쳤는지는 아래 세 절에 적었다.

## 회귀 확인 (`dev/`)

새 유형을 넣을 때마다 **전부 다시 돌린다.** 브라우저 콘솔에서:

```js
for (const f of ["/dev/cases.js", "/dev/sweep.js"])
  (0, eval)(await (await fetch(f, {cache: "no-store"})).text());
SWEEP(SAMPLES); SWEEP(DEVCASES);
```

보는 것: 추적기가 터지는가 / 블록마다 제목이 붙었는가 / 제목만 있고 속이 빈
블록이 없는가 / 같은 변수가 블록 둘로 나오지 않는가 / `update()` 가 터지거나
설명 줄이 비지 않는가.

**함수 안 프레임(`depth > 0`)을 반드시 훑어야 한다.** 예전에 전역 프레임만 보다가
"함수 안에 들어가면 화면이 통째로 빈다"는 버그를 22개 예제 통과시키며 놓쳤다.

`dev/cases.js` 는 드롭다운에 안 실은 확인용 코드다 (누적합 2D, 행렬 곱, 진법 변환,
좌표 정렬, 최장 공통 접두사, 톱니바퀴 회전, 뱀 시뮬레이션 등).

## 같은 자료형, 다른 그림

두 번째 목표는 "유형마다 고정된 그림"이 아니라 **이 코드를 가장 잘 설명하는 그림**이다.
같은 2차원 리스트라도:

| 코드가 쓰는 방식 | 그림 |
|---|---|
| 값이 0/1 뿐 | 지도 (찬 칸 / 빈 칸) |
| 값이 여러 가지 | 숫자 표 + 진하기 |
| 행 길이가 들쭉날쭉 | 그래프 |
| 2열인데 행 수가 변함 | 쌍을 담는 그릇 (안 그림) |
| 2열이고 모든 행이 앞<=뒤 | 구간 막대 |
| `tree[i]=tree[2i]+tree[2i+1]` | 완전이진트리 |

제목에 **무슨 그림으로 그렸는지** 항상 쓴다 (`0/1 지도`, `구간합 트리`, `# 강조`).
판정이 틀렸을 때 사용자가 바로 알아채려면 그게 필요하다.

재귀 + 배열/그래프가 섞인 경우도 **호출 스택과 자료구조가 같이** 나온다.
퀵소트는 `quick(lo, hi)` 가 쌓이는 동안 배열이 정렬되는 게 한 화면에서 보이고,
재귀 DFS 는 호출 스택 + 그래프 + `order` 배열이 동시에 움직인다.
